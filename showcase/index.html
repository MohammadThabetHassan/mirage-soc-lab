Controlled defensive security laboratory

Practice detection decisions with evidence you can inspect.

MIRAGE is a local-first SOC lab for deterministic telemetry replay, ATT&CK-aware detections, analyst disposition practice, and repeatable evaluation. It is built to explain what a rule needs, what it found, and where its conclusion must stop.

Practical use cases

Four exercises that make a detection useful.

Each exercise has a declared expected result. Positive scenarios show a defined rule path; benign and boundary scenarios show what should not become an alert.

Detection contract

A rule is more than a technique label.

Rule What it demonstrates Required evidence Analyst boundary
Repeated SSH authentication failures T1110 — Brute Force Failure event type, source, time, and account candidate A threshold match is suspicious in the lab, not a production verdict.
Successful login after repeated failures T1078 — Valid Accounts Source-bound failure sequence and later success inside the window Legitimate users can make mistakes; evaluate the surrounding context.
Multi-stage decoy engagement and discovery T1087 — Account Discovery Credential activity, decoy interaction, and allowlisted discovery evidence One inventory command alone does not form the complete lab story.

Start here

Move from a change to an explainable result.

  1. Read the contract. Review the rule threshold, expected benign case, ATT&CK context, telemetry prerequisites, and triage questions.
  2. Run the matching scenario. Use the controlled scenario to generate only the data needed for the stated exercise.
  3. Inspect the case. Validate the timeline, risk factors, analyst disposition boundary, and evidence integrity status.
  4. Verify the outcome. Check the evaluation matrix and run the test, type, build, browser, and security gates before sharing a change.
